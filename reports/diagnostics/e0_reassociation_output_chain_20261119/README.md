首断点是描述性链路分类，不等同于“重连失败”的分区：有 1 个事件未由注册正检测更新原轨迹，但 GT 当帧仍匹配到了原 ID（使用了另一检测）；故重连成功总数为 159、无断点类别为 158，实际重连失败是 672。不能用 `831−158` 代替失败数。

E0 明确检出了协议预设的 E1 触发实例，故可进入已冻结的成熟轨迹输出规则 U 四条件对照。该诊断只说明内部更新与输出之间存在断点，不证明 U 能改善官方 HOTA、AssA 或 IDF1；E1 才测输出代价。242 个关联断点和 4 个输出后 GT 未匹配事件仍需保留，不能将全部失败归为 `min_hits`。

每类按事件 ID 的 SHA256 固定选取至多两个案例，ID 列表在原始 `summary.json`；完整逐帧链路在数据盘 `window_frames/`，逐事件标签在 `event_rows/`。没有使用官方 val，也没有改动 B0 状态、检测缓存或旧结果。
