# E1：成熟轨迹重现后的输出规则 U

**范围：** 固定 8 段 DanceTrack train motion-dev，B0/CV 提案 × 原输出/U 输出的完整 2×2；开发集探索结果。
**协议：** `manifests/protocols/e1_mature_reemit_factorial_20261119.yaml`，SHA256 `0aba57b6214b45b6071cbc75d5fefda6be6425f696697b424aa23e264e00b249`。
**设备：** CPU，`CUDA_VISIBLE_DEVICES=''`，物理 GPU 无。

E0 在 424 个曾成熟输出的固定事件中观察到“正检测更新了原轨迹，但当帧无输出”，达到预先写定的 E1 触发条件。U 只对过去按原规则确认并输出过、当前帧又被真实高分检测更新但被原输出门省略的轨迹，额外发布当前检测框与同一 ID。U 不参与匹配、KF、历史或生命周期更新。

| 条件 | 首轮提案 | 输出 |
|---|---|---|
| A | B0/KF | 原规则 |
| B | B0/KF | U |
| C | CV | 原规则 |
| D | CV | U |

A/B 共用一次 B0 轨迹执行，C/D 共用一次 CV 执行；生成 U 输出时逐帧核对轨迹状态字节不变。A/C 的 16 份轨迹输出逐视频与历史参考一致（帧/ID 精确，框误差 ≤1e-4 像素）。U 分别增加 B 的 2,595 行、D 的 2,310 行；固定 GT IoU 0.5 匈牙利匹配下，其中 B 为 2,331 TP/264 FP，D 为 2,061 TP/249 FP。该新增行分类是内部代理口径，不能与 TrackEval 的 FP 逐项相等。

这些事件在同一开发集上按旧定义重评：当帧重连要求 GT 的实际输出匹配到原 ID，五帧持续要求后续四帧也保有该 ID。U 按构造改变的是可见输出，**不能改变内部身份配对**；事件改善与官方指标代价需同时解释。

协议还要求内部首轮配对数。主 E1 运行漏存此辅助字段，独立审计已指出；随后用只读附录补齐。B0 的 A/B 共用 E0 全量链路，注册正检测首轮配到 B0 原 ID 为 **575/831**。CV 的 C/D 按同样检测帧重新回放并与历史 C 轨迹逐字节核对；在缺失前用 GT IoU 0.5 匹配 CV **自己的**输出 ID 后，806 个事件有 CV 先决身份，其中 494 个注册正检测首轮配回该 CV ID。若机械地拿 B0 ID 衡量 CV，只有 102 次，**102 不能解释成 CV 身份正确数**。这些是事后补录的描述性内部指标，B0/CV 的状态与可评价分母不同，不能用 575/831 与 494/806 直接作方法优劣检验，也不参与 E1 门槛。

## 预定决策与边界

预写判据中，“B0 与 CV 的 HOTA 都不提高则关闭 U”未触发。CV 条件 D−C 的 HOTA、AssA、IDF1 均提高，因此 U **可保留为下一轮简单强化基线**；B0 条件的 AssA 下降，不满足同一条继续判据。这里的 AssA 增量只有 +0.035 点，且 IDSW/Frag/FP 增加，下一轮必须把误恢复风险作为核心约束。U 不是已确认的新方法或毕业设计创新点；本轮没有官方 val 确证，也没有证据说明内部匹配已经改善。
