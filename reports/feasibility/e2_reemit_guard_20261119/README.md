# E2：成熟轨迹再输出的简单风险门控

**范围：** DanceTrack train 内已反复使用的 8 段 motion-dev；只重排 E1 的 CV 轨迹输出，不重跑 tracker。协议 `manifests/protocols/e2_reemit_guard_20261119.yaml`，SHA256 `479e2e4203ac31be867620b9a7bb1dac7fe495e90051de9dfa4265f369dc131f`。CPU，`CUDA_VISIBLE_DEVICES=''`，未使用任何 GPU。

## 风险与先例

E1 的 CV+U 相对 CV 原输出：HOTA +0.477 点，但 IDSW +91、Frag +174、官方 FP +328。对 E1 新增行做固定 GT IoU 0.5 匈牙利代理匹配：2,310 行中 2,061 TP、249 FP。新增行中检测分数低于 0.8 的 1,390 行含 227 代理 FP；分数至少 0.8 的 920 行含 22 代理 FP。连续命中 1 的 1,254 行含 168 代理 FP，连续命中 2 的 1,056 行含 81 代理 FP。逐视频及 gap 分布在数据盘风险摘要；这些是**查看开发集标签之后**得到的探索性分布，不能当独立证据。

已核查官方实现：[OC-SORT](https://github.com/noahcao/OC_SORT/blob/master/trackers/ocsort_tracker/ocsort.py) 用 `hit_streak >= min_hits` 管理输出；[Deep SORT](https://github.com/nwojke/deep_sort/blob/master/deep_sort/track.py) 用 tentative/confirmed 和 `n_init` 管理轨迹确认；[ByteTrack](https://github.com/FoundationVision/ByteTrack/blob/main/yolox/tracker/byte_tracker.py) 对 lost track 再激活，并按检测分数划分候选。E2 的分数/连续命中门控与这些生命周期和置信度思想明显重合，**只是简单对照，不是新方法主张**。这些实现并不与本项目的精确输出规则逐行相同；这里评估的是本机风险收益，未完成全面新颖性检索。

E/F 均满足预写的**探索性效用门**：相对 C，HOTA/AssA/IDF1 增加；相对 D，IDSW/FP 减少。E 的风险收益更好，但这不是冻结选模或统计显著性结论。E 相对 C 仍多 39 次 IDSW 和 42 个官方 FP，且减少了 U 的部分恢复收益。8 个视频的 E−C HOTA 都为正；视频 0020 的 E−C AssA 为 −0.038 点。逐视频原始值见 `summary.json`，不能只看聚合值。

固定 831 事件的五帧持续成功 C/D/E/F 分别为 84/328/167/89；E/F 的重连数为 256/152，D 为 559。E 的新增输出按同一代理口径为 898 TP/22 FP，F 为 975 TP/81 FP。代理新增行 FP 与 TrackEval 官方 FP **不是同一口径**，也不能将 IDSW 增量逐行归因给特定输出。
