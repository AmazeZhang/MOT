# 实现步骤与接口约定

状态：待实现。本文不是已经存在的代码说明；下列 `src/`、`scripts/`、`tests/` 只是拟定结构。目前不提供虚构的训练 CLI。

## 1. 实现顺序与验收

| 里程碑 | 拟实现模块 | 验收要求 | 对应验证 |
|---|---|---|---|
| M0 | 环境盘点、来源记录、数据校验器 | 单卡 CUDA/NMS，数据数量与格式，坏文件定位 | G0 |
| M1 | 检测导出、OC-SORT 缓存重放、TrackEval 调用 | 一段视频全流程、空帧、官方人工指标例、重复运行 | G1 |
| M2 | 事件日志、失败视频、诊断分析 | 输出能追溯到检测/轨迹/时间，不给“遮挡”伪真值 | G2 |
| M3 | 轨迹样本、统一编码器、回归/Gaussian/MDN | 没有跨序列 ID 合并；小样本能拟合；闭环可运行 | G3 前半 |
| M4 | CFM 损失、采样器、核兼容度 | 采样数/步数可控；数值有限；对照与效率曲线 | G3 后半 |
| M5 | 关联标签、dustbin、监督与梯度控制 | 关联分支的梯度路径通过检查；无 GT 候选泄漏 | G4 |
| M6 | 多种子汇总、配置冻结、第二数据适配 | 正式协议、完整方法对照、失败与负结果归档 | G5 |

每个里程碑形成独立 Git 提交或短分支。先在一段 train 视频和几十/几百帧上验收，再扩大。不要同时编写所有模块后才首次运行。

## 2. 拟定目录

```text
src/mot_research/
  data/           # 格式、划分、轨迹样本、训练用 GT 映射
  models/         # 共用 encoder；regression/gaussian/mdn/cfm
  association/    # 核分数、门控、dustbin、训练代理
  tracking/       # 上游适配、状态与历史、生命周期日志
  evaluation/     # 官方评测调用与结果读取，不自写 HOTA
  analysis/       # 事件、分桶、视频配对、可视化
scripts/          # 各阶段入口，实际创建后才写执行说明
configs/          # 已验证运行配置；路径不硬编码
manifests/        # 数据/权重/检测/上游版本和划分清单
tests/            # 坐标、因果性、梯度、评测关键用例
docs/             # 当前手册与实验结论
```

优先纯 PyTorch、NumPy、SciPy，少引入框架。第一版 CFM 采用固定步长 Euler，可直接表达所需反传路径；不必先引入通用 ODE 或 diffusion 工具库。

## 3. 数据契约

`FrameDetections`：sequence_id、frame_id、image_size、timestamp/fps、boxes_xyxy[N,4]、scores[N]、det_ids[N]；不含 GT ID。空帧使用形状正确的空数组，不能跳过时间更新。

`TrackHistory`：track_id、frame_ids[L]、boxes[L,4]、is_observed[L]、is_valid[L]、elapsed_time；每视频重置。若记录预测框，必须显式标记，不能混成真实观测。训练专用 GT 标签保存在另一对象，在线 tracker 不接收该对象。

`MotionOutput`：samples[B,K,4]、可选均值/协方差/混合权重、归一化版本、采样 seed/step；全部表示同一个目标时间。确定性模型作为一个样本，不人为复制噪声后冒充多模态模型。

`AssociationBatch`：历史、当前候选检测、合法候选 mask、正匹配索引或 dustbin、ignore 标记、样本序列键；标签仅用于 loss。不存在正检测时使用 dustbin，GT 匹配含糊时忽略该监督项并统计比例。

## 4. 明确坐标与时间，避免隐蔽偏差

第一版建议对所有轨迹用相同图像尺度：

\[
b=(c_x/W,\ c_y/H,\ \log(w/W),\ \log(h/H)),\quad y=b_t-b_{last}.
\]

目标检测和每个轨迹样本都转换到此状态的增量空间；全局标准化统计只在 motion-train 拟合并冻结。该定义不随各轨迹宽高改变尺度，便于跨轨迹比较匹配代价。

若后续改成按每个目标的宽高标准化，密度单位会随轨迹变化，需要处理变量变换的 Jacobian 或明确仅为学习分数，不能直接把不同尺度的密度当作同单位 likelihood 放入 Hungarian。第一版避免这项额外复杂性。

框还原先恢复状态再 exp 宽高，验证 encode/decode 往返误差；数值裁剪、画面外处理对所有方法一致并记录。`frame_gap` 是目标帧减最近有效观测帧，`missing_count` 通常是 gap−1，二者不混用；跨数据的真实秒数从 seqinfo fps 推导，缺失 fps 时单独标注。

历史里不允许当前帧匹配之后的框提前进入本次预测。训练可以使用未来 GT 作为目标，但条件特征只能来自允许的历史和当前检测集合。用“改变未来帧不影响当前输出”的用例检查严格在线性。

## 5. 如何接入 OC-SORT

**第一版定位为关联运动先验，不宣称完全替代 KF 的滤波与状态更新。** 保留基线的 KF/ORU 状态、更新、轨迹出生删除与输出规则；研究预测器读取历史真实观测，在关联阶段提供候选兼容度。

上游源码包含首轮关联、可选低分二次关联、旧观测重匹配；不能只替换一个 `predict()` 返回值就认为所有运动逻辑已替换。[OC-SORT 源码](https://github.com/noahcao/OC_SORT/blob/master/trackers/ocsort_tracker/ocsort.py)

实现分两个模式：

1. `baseline`：完全沿用原始代价和门控，用于逐帧一致性检查。
2. `research`：共用研究代价接口，明确只作用于第一轮匹配；低分二次关联、重匹配和生命周期保持相同。KF 也通过同一 research 接口形成 B1，以隔离代价接口改动。

若原先基于 KF/IoU 的硬门控已经排除了真候选，FM 再好也无法恢复。先统计排除率；为 research 模式选一个固定、较宽的几何候选规则，所有预测器共用，额外候选数与延迟要报告。不要只给 FM 放宽门控。初期不启用额外外观特征。

每帧日志应能辨认首轮/二次关联/重匹配的决定；如果 FM 收益全被 fallback 掩盖，应分析而不是直接删掉对 baseline 有利的逻辑。更改多轮匹配策略属于独立实验。

上游空检测输入要求逐帧调用，`None` 和形状为 `[0,5]` 的数组可能有不同时间推进效果；适配器使用经确认的空数组路径。原图缓存传入会再次缩放的接口时，应正确设置原图尺寸或绕过重复缩放，并以叠加图验证。

## 6. 预测器与概率分数

共用 GRU 编码器输出历史条件；不同头分别实现均值回归、Gaussian 的均值/方差、MDN 的混合分量和 CFM 向量场。不先加入复杂邻域网络。

Gaussian/MDN 用 softplus＋方差下界，MDN 用 log-softmax 混合权重和 log-sum-exp，监控单分量独占。CFM 的线性路径监督与推理分别实现，训练采样时间 `s` 与实际视频时间严格区分。

初期统一核兼容度，匹配检测的增量与预测样本相比较。记录 bandwidth，不把放宽带宽的收益归因于多模态；对 Gaussian/MDN 可另测与该核卷积后的解析密度，以区分样本近似与模型差异。不要把未卷积的 MDN 密度与加核平滑的 FM 结果无说明地混为一个比较。

每条轨迹有未匹配选项。实现可用各行专用 dummy 列，禁止其他轨迹使用该列，剩余未匹配检测进入原来的新生逻辑。训练的 dustbin 与推理拒配代价需对齐；不能训练允许拒绝、推理却强迫所有行匹配。

## 7. 关联监督怎样实现与排错

训练正负对应由当前帧检测与 GT 一对一匹配得到，结合轨迹标签。固定标注 IoU 门槛、忽略规则和重复检测策略，记录无匹配/含糊样本比例。困难负样本按推理可获得的空间信息选择；不能用未来正确身份来构造推理特征。

联合损失保留各模型自己的运动目标，再加统一关联代理。第一轮各变体用相同总更新数，前 20% 更新只训练运动目标，之后 joint 开启关联项，motion-only 继续原目标；这一比例是起点，调整需登记。若共享预训练 checkpoint 分叉，注明配对关系、相同初始化来源及总计算，不把分叉当作独立随机重复。

关联监督需要两项独立反传检查：

- 只对 `L_assoc` 调用反传，joint 版本的运动生成参数梯度有限且非零。
- detach 版本的生成参数不接收关联梯度，但匹配头仍有梯度；`L_motion` 的梯度另行测试。

CFM 从独立噪声走完整的少步 Euler 链得到关联候选。不能在训练分支使用 `no_grad`、`inference_mode` 或不小心 `detach`。标准 Hungarian 只用于推理/标签构造，行交叉熵是代理，不声称直接优化离散全局最优分配。

若为省显存采用截断反传或代理终点，必须作为不同配置，并对比其信息条件与部署采样。已有 DiffMOT sampler 的 detach 不能直接沿用到联合训练。

## 8. 关键验收用例

只围绕会影响科研结论的行为写测试，不为文档或简单包装堆测试：

- 同 ID 在不同视频不连接；划分清单无交集；标准化不读 dev/val。
- 编解码往返、空帧、单目标、不同图像尺寸、frame 1、宽高边界。
- 完美/漏检/ID 交换的官方评测例；缓存重放与原始 baseline 一致。
- 所有候选被拒绝、目标新生/消失、同帧一对一约束、重复检测。
- 给定 seed 的采样形状和数值；改变未来图像不改变当前输出。
- `L_assoc` 的 joint/detach 梯度路径；K=1/S=1 与多步形状。
- 同一 checkpoint 在自然与人工缺失的固定清单上运行；resume 保留优化器、随机状态与进度。

G3 可用极少量训练样本过拟合来检查实现，但此结果不作为泛化证据。断点恢复的精确数据顺序若未保证，应明确记录其差异，不能称完全等价重跑。

## 9. 每个 run 的最低产物

配置快照、Git SHA/dirty 状态、依赖版本、数据/检测/划分 hash、模型参数量、训练与推理种子、训练曲线、checkpoint、完整 tracker 输出、TrackEval 输出、逐视频摘要、峰值显存/时间和失败原因。run_id 唯一且不覆盖旧输出。

正式比较用干净提交启动；开发时的未提交变更至少保存 diff。发布表格前由原始结果重建，不能手工挑选最优文件覆盖同名输出。
