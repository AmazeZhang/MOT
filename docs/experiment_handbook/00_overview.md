# 实验手册总览

版本：2026-11-10 / v0.1。适用对象：毕业设计初期研究，8 张 RTX 4090 与 1 张 RTX 3060 12GB。尚未确认它们是否在同一台机器、GPU 使用权限与软件环境。

## 1. 现在需要确定的基本需求

目标是在公开数据集上得到可复现、能解释机制的研究结果。第一轮不预设 FM 一定优于简单模型，也不承诺最终毕业创新点数量。

| 已确定 | 当前默认选择 | 尚需服务器反馈后决定 |
|---|---|---|
| 单摄像机在线 2D MOT | DanceTrack 为首个数据集 | 系统、驱动、存储路径、网络条件 |
| 关注短缺失、交叉后的身份关联 | 固定检测缓存，无 ReID | 8 卡分布、可用时段、调度方式 |
| 方法需要与简单模型公平比较 | 轻量 GRU＋不同预测头 | batch、worker、并发任务数 |
| 使用官方评价体系 | 独立 TrackEval 评测环境 | 旧检测器可运行的准确依赖版本 |
| 先验证再扩大工作量 | 单卡、少量配置起步 | 学院毕业要求、计划时间与预算 |

第一轮暂不做：重训检测器、3D 重建、长未来轨迹生成、ReID 联合训练、8 卡 DDP、蒸馏、动态采样、直接生成分配矩阵、离线平滑。这些可以在证据支持时加入。

## 2. 推荐执行顺序

| 阶段 | 工作 | 必须交付 | 继续条件 |
|---|---|---|---|
| G0 准备 | 反馈硬件，选环境，下载 train/val | 服务器清单、依赖快照、数据校验清单 | GPU/数值/磁盘与数据格式验收通过 |
| G1 基线闭环 | 官方 OC-SORT，冻结检测，官方 TrackEval | 一段短序列闭环、缓存一致性、完整基线记录 | 输入/输出坐标正确，评测可信，可重复 |
| G2 错误归因 | 分析缺失、偏移、交叉与历史污染 | 分桶统计、可视化样例、诊断对照 | 确认值得改进的运动关联错误 |
| G3 预测器筛选 | 回归/Gaussian/MDN/FM | 开环与闭环对照、耗时、失败样例 | FM 有增量价值，或清楚找到更合理方向 |
| G4 关联监督 | 控制损失和梯度路径 | 预测器×监督矩阵、停止梯度对照 | 生成器改变带来可重复收益 |
| G5 深入验证 | 多种子、第二数据、完整方法对照 | 锁定协议、统计、效率与论文证据链 | 形成可信毕业设计贡献 |

G0–G2 不需要 FM 训练。G3 的单种子结果只是筛选，不作为最终结论；不通过时先排查实现或调整问题，不强行推进 G4。

每个阶段结束时，同步检查 [创新主张台账](../research_governance/innovation_registry.md)：实验结果只能支持已登记的 claim，新的文献先例或负结果必须使主张降级、收缩或改写。

## 3. 本轮交付与后续分工

本轮交付的是手册、接口设计、填写模板和 [研究监管台账](../research_governance/README.md)。仓库还没有 `train.py`、数据转换器、检测缓存器或 FM 实现；文档中标为“拟实现”的命令与接口不可执行。第三方仓库命令也必须在对应工作目录运行，不能直接在本仓库执行。

你看完之后，可以先按 [环境手册](02_environment.md) 收集只读信息，并按 [数据手册](03_data_and_evaluation.md) 准备 train/val。填写 [服务器模板](../templates/server_inventory.md) 后反馈。届时我们确定环境版本和第一批实现任务，再开展 G1。无需现在发送服务器密码或私钥。

## 4. 第一批算力预算原则

- 起步只申请 1 张 4090，先跑一段视频和小批次 smoke test；观察显存、GPU 利用率和 I/O。
- 简单模型正式比较可以逐步并行至 2–4 卡；确认 CPU/RAM/存储没有瓶颈后再扩大。
- 8 卡优先用于不同模型/种子独立任务。不要把 3060 混入首轮同步训练。
- 不估计未经实测的小时数。先记录一段数据导出耗时、每 epoch 样本数与速度，再外推总预算。
- 预先记录每阶段最多允许的配置数和 GPU 小时；超预算时留下原因，不能无限调参直到 FM 胜出。

## 5. 第一轮最重要的三个决定

1. **预测器能解决什么错误？** 若主要问题是检测偏移或状态污染，先考虑观测/历史建模。
2. **是否需要 FM？** 若 MDN 在相同输入与预算下同样有效，可以保留分布研究、调整生成机制。
3. **是否需要关联监督回传生成器？** 若只训练读出头就足够，不把收益归功于生成分布学习。

学院是否要求两个方法贡献、系统成果或论文发表，留在反馈模板中明确；目前不以增加模块数量替代研究工作量。
