# 2026-11-19 更新复盘：下一步聚焦再关联与输出之间的断点

本次核对基于本地 HEAD `502d7df`、R1/R2 报告与协议、相关实现和审计摘要。没有连接服务器、重新计算数据盘原始产物或启动实验。以下是新的研究建议，**尚未冻结、实现或运行**；旧分支的停止结论保持不变。

## 1. 当前判断

下一步优先研究：**观测缺失后，已经存活的轨迹如何完成可靠再关联，并转化为持续身份输出。** 第一项工作是拆清“没匹配上”“匹配上但没输出”“输出后再次丢失”，随后做一个最小输出策略对照。暂不训练 FM、扩散、MDN，不继续堆 R1 选择器，也不调 R2 打分超参数。

这不是已经成立的新方法或创新点。它是现有证据最直接支持、且可以用现有 CPU 回放平台较快证伪的问题。给这一轮诊断和简单对照合计 **2–3 个工作日的实施预算**，不再无限追加解释性实验。

## 2. 新实验实际说明了什么

| 尝试 | 核心证据 | 可以得出的结论 |
|---|---|---|
| P1 学习运动 | motion-dev：KF HOTA 50.060，CV 51.057，学习模型三 seed 均值 49.271 | 离线预测改善没有转化为当前接口下的闭环收益；CV 是必须保留的简单强对照 |
| R1 成对动作价值学习 | 1,426 个动作；训练内留出 320 个、各策略等量选 83 个；未来线性 +168、即时线性 +60、简单 IoU +239 | 未来监督有信号，但当前模型没有超过简单规则；按原门槛停止，不升级 MLP |
| R2 同状态分布打分 | S1 正确 545/829；S2/S3/S4 相对救回 57/91/64，伤害 38/63/39 | 分数改变会改变排名，也有明显代价；三者都不满足 ≤2% 伤害门槛，不进入原 P2 |

R1 的单位是独立成对分支中、可能重叠的 10 帧窗口的身份正确帧差之和，不是一起执行 83 次动作后的跟踪增益。R2 的单位是指定检测对轨迹的 top-1 排序，不是全局分配或持续身份。R2 净正确数分别增加 19/28/25，所以不能将门槛失败写成“打分不敏感”或“没有任何改善”。同样，R1 只测了固定动作、13 个特征和线性模型，不能写成“动作价值学不出来”。

目前已经产出了有价值的实验平台、可复用标签和负结果；**仍没有经过确认的新在线方法收益和明确创新性结论**。下一阶段需要闭环证据，不需要以更多模型名字填充工作量。

## 3. 对新增建议的取舍

仓库可核对的是 [决策规则草案](next_branch_decision_rule_plan_20261118.md) 和 DiffuTrack 阅读记录；未找到单独标注为 DeepSeek 原始对话的文件。因此以下评价针对落盘方案，不把具体错误归因给某个建议者。

### 应保留的部分

- 在同一假设集下比较规则，避免把生成器变化与决策变化混在一起。
- 区分匹配、轨迹状态演化和输出，避免把单步 IoU 当成跟踪效果。
- 先用便宜的简单方法查可行性；FM 只应是问题确立后的候选实现。

### 需要纠正的部分

1. **不能从 DiffuTrack 的 fallback 触发率、再关联率或作者解释，直接推导“收益主要来自轨迹不死”。** 这些统计缺少同配置关闭 fallback 的反事实。表 10 的相同 AssA 也只约束该表所比较的输出配置，不能完成整个系统的贡献归因。本次网页核查读到方法介绍，后续表格请求被 Nature 登录重定向阻断；具体表格数字沿用已有全文阅读记录，未声称本次独立复核全文。
2. **本项目的轨迹大多没有死。** 固定事件中 829/831 个目标轨迹在重现帧仍存活。仅延长目标轨迹寿命在这组事件上直接作用的空间很小。这不代表所有 DanceTrack 事件或更长缺失都如此，也不排除竞争轨迹生命周期的间接影响。
3. **三组不能分解完整交互。** 原 P3 有“新打分/原续轨、旧打分/新续轨、新打分/新续轨”，缺少同实验中的“旧打分/原续轨”。如果以后做该问题，必须完整 2×2，并精确定义续轨究竟改了什么。其他假设集、候选资格和外观项也必须一致。
4. **均值 IoU 不等于似然，不代表它就是错误决策。** 期望 IoU 对应一种效用；密度评分依赖分布、核宽、检测噪声和身份先验等假设。S2 会偏好偶然覆盖，S3 也不会自动解决身份竞争。不能把“概率正确用法”当成 S3 优势的证明。
5. **HOTA 的总体分解不能直接使用汇总后的平方根乘积。** 官方 HOTA 对不同定位阈值上的 `sqrt(DetA_alpha * AssA_alpha)` 求平均，一般不等于 `sqrt(mean DetA_alpha * mean AssA_alpha)`，参见[固定版本 TrackEval 实现](https://github.com/JonathonLuiten/TrackEval/blob/12c8791b303e0a0b50f753af204249e622d0281a/trackeval/metrics/hota.py)。草案中的 25%/75% 和 92% 不能作为严格贡献比例；即便按阈值做算术分解，也不是因果归因。

## 4. 当前最值得追查的具体证据

既有共同状态诊断中，B0 有 **575 次首轮正确匹配，其中仅 158 次符合重连指标**：差额 417 次。另有 1 次重连来自首轮正确匹配集合之外。这比继续比较几种排名函数更值得先解释。

本次核对了固定提交的 [OC-SORT 实现](https://github.com/noahcao/OC_SORT/blob/bb2f6867a41082558d95ab47a854a3918de7831b/trackers/ocsort_tracker/ocsort.py)：默认 `max_age=30`、`min_hits=3`；缺失后预测会重置 `hit_streak`；重现匹配会增加计数，但输出仍要求当前有更新且连续命中达到门槛（视频启动阶段有例外）。本项目 [运行器](../scripts/run_p1_natural_closed_loop.py) 没有覆盖这两个默认值。

因此，**内部匹配正确但暂不发布该轨迹**是代码上确实存在的通道；是否解释上述 417 次、解释多少，仍需逐事件证据，不能现在报一个比例。检测的 GT 缺失不等于 tracker 完全没有更新；GT 与检测、GT 与输出框的两次全局匹配也可能不同，不能把所有差额都归到 `min_hits`。

现有 [事件评价](../src/mot_research/evaluation/closed_loop_events.py) 要求重现当帧输出同 ID，持续成功还要求随后五帧每帧都有同 ID。因此“恢复失败”包含输出缺失，不全是身份切换。这不是废弃旧指标的理由：用户看得到的跟踪输出确实重要；但它不足以单独定位身份决策错误。官方 TrackEval 结果仍有效，也不能因为新解释而覆盖旧负结果。

## 5. 下一轮最小执行方案

### E0：一次有界的事件链路核对，约半天至一天

先写一个新协议，明确是读过 R2 结果后的探索性机制验证，保留原事件和旧指标。

以全部 8 段 motion-dev 的 B0 完整回放为主体，覆盖原 831 事件。首次只做 B0；需要解释方法差异时，再加入既有 CV，最后才考虑固定最早 seed `20261112` 的 learned，不能按结果挑 seed。

记录重现帧及之后至少 5 帧的链路：

| 层次 | 必须记录 |
|---|---|
| 存活与身份 | 原目标 ID 是否存活；是否已在缺失前污染；是否过去确认/输出过 |
| 匹配 | 正检测是否入池、目标配对是否过门；首轮与 OCR 最终配对；目标是否改配他人 |
| 更新 | 更新前后 `hit_streak`、`hits`、`time_since_update`；真实观测是否写入 |
| 输出 | 是否被输出门抑制；实际返回框/ID；文件是否有该行 |
| 评价 | GT 对实际输出的分配；无框、错 ID、框不匹配分开；首次重新输出同 ID 的延迟；随后再次丢失或换 ID |

建立一张互斥的“重现当帧首个断点”计数表，同时保留可重叠的次要标记；后续五帧单列，不能把计数相加后重复解释同一事件。831、829、575、158 与已有报告衔接，未解释部分明确保留。GT 只能在记录结束后作标签。

重点验收：零改动回放与原 B0 一致；新增记录不改变状态；无输出和错身份分别计数；抽查固定哈希选出的事件，而非只展示成功视频。抽取少量类别案例供人阅读，全量计数覆盖全部事件。

**这一阶段回答的是断点在哪里。** 没有输出抑制实例，则跳过 E1；有实例则做 E1 测实际代价，不靠事后挑一个“大于多少”的百分比宣布机制成立。

### E1：成熟轨迹重现输出的最小对照，约一至两天

定义一个不学习的输出规则 U：**过去已经按原规则确认并输出过的轨迹，当帧真实检测再次匹配成功时，立即发布该检测框与原 ID；从未确认的新轨迹继续遵守原确认规则。** “过去确认”精确定义为此前某帧 `hit_streak >= min_hits` 且已输出；不能把视频启动宽限期内未经连续确认的输出算作成熟轨迹。

U 不补预测框、不用未来帧、不放宽关联门、不延长 max_age，也不让输出决定反馈到匹配、KF、历史或生命周期。额外“曾确认”标记只供输出使用。它比全局 `min_hits=1` 更干净，后者同时改变新生假轨迹的过滤。

| 条件 | 已验证的首轮提案 | 输出 |
|---|---|---|
| A | B0/KF | 原规则 |
| B | B0/KF | U |
| C | CV | 原规则 |
| D | CV | U |

这是 **提案×输出** 的完整 2×2，不是绕过 R2 门槛运行 S2/S3/S4。A/B 内部轨迹状态和所有配对必须逐帧一致；C/D 也一样。因此可以各回放一次，分出两份输出，再分别评测。历史 A/C 可作一致性参考，但新实现仍须验零改动。

预先报告：官方 HOTA、DetA、AssA、IDF1、IDSW、Frag、FP/FN；原 831 事件的重连、五帧持续、恢复/伤害；新增输出 TP/FP、恢复延迟；独立的内部配对身份正确性。内部指标的 GT 映射及 IoU 阈值须事前固定，注明不是官方指标。

按视频报告 `B−A`、`D−C` 和交互 `(D−C)−(B−A)`；全部官方汇总仍通过 TrackEval 计算，不能平均视频 HOTA 来替代。8 段视频是重复配对的开发单元，不能把 831 事件当 831 个独立视频，也不能把原先挑过的开发集称为新验证集。

本轮先用以下**预算决策建议**，执行前写入协议，不能看结果后改：

- U 若在 B0 和 CV 上均不提高整体 HOTA，关闭这一输出规则候选，保留分解结果。
- 只有 HOTA 提高且 AssA、IDF1 不降的条件，才值得进入下一次方法设计；同时完整报告 FP/FN、IDSW 和逐视频损伤，不能用单个指标掩盖代价。
- 即使通过，也只代表一个简单输出策略在开发集有效。U 按构造不能改变内部身份配对；AssA 变化也不能声称修好了内部关联。它应先成为强化基线，不能直接包装为毕业设计核心创新。
- 若 U 解释了大部分事件代理改善，但 CV 与 learned 的闭环差距仍在，明确把“代理受输出影响”和“模型闭环失败原因”分开，不再尝试用一个原因解释全部现象。

### E2：只沿一个有证据的断点深入

- **主要是匹配后输出抑制：** 先将 U 作为简单基线。只有看到可观测的误恢复风险，才考虑“成熟轨迹再确认规则”；必须与已有生命周期/置信门控方法做专项重合检查。
- **主要是恢复后错更新、身份再次切换：** 研究“重现观测何时允许写入运动/身份状态”。先做一个明确的更新动作反事实，保持分配、输出、存活分开；不要同时加不确定性、ReID 和生成器。过去 D1 的窄范围阴性结果也要保留作约束。
- **主要是正确目标在拥挤候选中无法区分：** 停止继续堆纯框运动分布；评估外观信息的增量价值。先固定现成表征作信息来源对照，再决定是否训练；这需要新的范围和文献审查，不在本轮自动启动。
- **没有稳定可干预断点、简单对照也无收益：** 结束本支。重新选择论文问题，不再以扩大模型或添加诊断延续当前假设。
