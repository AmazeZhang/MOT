# 研究端实验指导与 A2A 任务规范 v1

生效：2026-11-25。研究端负责“为什么做、具体做哪几组、结果怎样改变决定”，服务器端负责实现、执行和证据交付。与 [实验报告规范](experiment_reporting.md) 配套；入口为 [AGENTS.md](../AGENTS.md)，当前任务只从 [LATEST](a2a/LATEST.md) 领取。历史手册不是待执行队列。

## 1. 每轮交付与责任

研究端交付一份 [任务书](templates/server_experiment_task.md) 和一个版本化协议，避免只写“尝试某方法”“补几个实验”。任务书供人理解，协议供锁定设计；两者矛盾时先修正文档，服务器不得自行选择有利版本。任务书注明协议路径；运行前生成带时间和 SHA256 的执行快照，不靠文件名宣称已预注册。

| 研究端必须决定 | 服务器可以落实 | 不能默默改动 |
|---|---|---|
| 问题、主张范围、对照、因素、数据职责、种子、选模/停止规则、预算 | 环境安装、数据路径、入口脚本、配置组合、指标导出、日志和证据生成 | 换数据/检测器/权重、重划 split、换损失、改主指标、改选模、增加调参/种子 |
| 每阶段输入、输出、通过后动作、失败后动作 | 预算内路径/API/空输入/存储兼容修复；不改数学语义的调试 | 把旧失败覆盖、从最好 checkpoint 事后改口径、扩大任务直到出现好结果 |
| 现有证据及已知泄漏/数据复用、需要回答的唯一决策 | 下载核验、实际依赖锁、数据加载成员核查、资源测量 | 把训练集改称最终测试集，把官方预训练结果当受控消融 |

服务器实现命令不是科学自由度：研究端仍要写清可执行语义。未知依赖版本、下载资产内容等可列为前置阶段的待解析项，并写出选择顺序和失败出口。关键科学选择不能一直留作 `TBD` 到看结果后再填。

## 2. 下发前的最小完整性

任务须回答以下十项，工程任务可填“不适用＋理由”，不必写成论文：

1. **身份与状态：** task ID、版本、日期、前置报告、替代/停止范围；设计完成、环境锁定、实际执行状态分开。只保留一个当前任务入口。
2. **问题与决定：** 一个主要问题，支持/不支持/不确定分别导致什么行动；复现、可行性、方法比较、机制验证、独立确认分别标识。
3. **实验矩阵：** 每组 ID、角色、唯一变化、共享输入、初始化、seed、数据范围、重复数、预期运行数量。工程 smoke 不混入主结果。
4. **数据与 GT：** 精确列表或已有不可变 split 路径/哈希、帧范围、历史使用、训练/选模/评估职责、预训练重叠。GT 的训练监督和离线评测合法，但不能进入在线特征/触发/配对。
5. **方法与对照：** 核心公式/接口/损失/输出含义，最强相关基线；涉及效用/拒绝时检查解析零点、恒定策略、动作类型常数；涉及学习时区分有效参数、更新步数和样本暴露。无需为无关平台验收强塞消融矩阵。
6. **执行与实现：** 顺序、依赖、实现责任、官方来源、已实现入口或明确待实现项；真实运行必须记录完整命令、解析后的配置、源代码及缓存身份。
7. **验收与停止：** 每阶段可观测通过条件、允许的修复范围、修复/时间/算力上限、部分完成如何报告、通过后是否自动继续。工程通过不等于研究假设成立。
8. **评估：** 主指标及单位、配对单位、checkpoint 选择、何时看开发/最终集、次要指标与代价。门槛应说明是投入决策值还是统计证据；不要把人为的 `+0.5` 当显著性界线。
9. **回传：** 各阶段文件清单、每张表的分母/覆盖、原始来源、曲线、案例及其抽样规则；引用 [报告规范](experiment_reporting.md)，不另造不兼容字段。
10. **决策边界：** 明列本轮不执行项；任务末尾写“完成后停在哪里”。失败优先回传可定位缺口，不能自动改做另一套研究。

## 3. 有界自动执行

用户将任务交给服务器执行后，已声明的阶段在前置门通过且预算尚足时自动推进，不为已授权的普通修复反复等待确认。报告阶段结束/失败/预算耗尽时回传；没有进展的轮询不算报告。达到资源上限立即保留 checkpoint/日志，记录未运行组。

任务书必须区分两种改动：

- **工程兼容修复：** 依赖/API、路径、空输入、导出、明确无语义变化的代码缺陷；保留补丁和重试 ID，执行针对性验证。调 batch/精度可能改变训练，不自动视为无语义变化；只能按预写分支落实并披露。
- **研究变更：** 控制组、输入、架构、损失、数据划分、选模、门槛、增加预算等；先形成新版本，注明是否已看结果及已有授权范围。超出用户授权的部分停止并说明原因。已有负结果不失效，也不允许覆盖成新版本结果。

不要求每个异常都重开整轮，不要求为了凑模板跑无意义实验，也不要求每个小任务找额外 agent 审计。

## 4. 回传后研究端怎样审阅

先核计划组/seed/视频与完成覆盖、权威 attempt 和实际配置，再检查可访问的原始指标导出、算术、单位、来源哈希。服务器路径不可访问的内容明确标注“引用服务器报告”，不冒充独立复现。

随后分别回答：工程是否可信；数据/对照是否允许该比较；学习是否改变了正确的决策；闭环是否收益且代价可接受；结果支持哪一级主张。学习 loss、局部 oracle、总体跟踪、方法创新不是可互换的证据。

案例须确认真实参照政策和稳定身份映射；同状态反事实不能用独立闭环轨迹替代，G proposal 不能写成 M。局部标签不代替官方 IDSW；相关帧/窗口不当独立样本。

最终给出一个主动作：继续预定确认、停止当前方法、先修一个明确工程问题，或另立不同问题。若补证据，列出缺什么、是否可从已有产物导出、最多投入多少、什么结果会改变决定；不能连续追加无法改变决策的诊断。

## 5. 文件组织与轻量回信

任务在 `docs/a2a/<TASK>_...md`，协议在 `manifests/protocols/`，结果在 `reports/` 对应类别；执行脚本和安全配置进入 Git，大型数据/模型/输出留在数据盘。沿用 [report_bundle](templates/report_bundle/README.md)。`LATEST` 只导航当前任务、权威报告、执行状态、限制和下一步。

服务器的用户可读回信统一为：**任务/版本 → 完成哪些组 → 主结果或工程验收 → 失败/偏离/限制 → 权威报告路径 → 已到哪个停止点、下一步需要研究端判断什么**。不能只写“跑完了，见服务器目录”。本地研究端交接同样说明完成与未完成。更新进展日志、相关索引；没有明确 Git 授权则保留工作树，不提交推送。
