## 2. 恒速必须保留，但不是已经找到的毕业设计方法

恒速相对 B0 的 HOTA 增加约 0.997 点、AssA 增加 0.961 点，IDF1 仅增加 0.051 点。在固定持续性事件上，B0 成功 81/780，恒速为 `81 + 23 − 20 = 84/780`；三个 P1 分别为 79、78、79/780。

恒速损伤 20/81（24.69%）个 B0 成功对照。这个比例只针对预定义对照组，不是全部轨迹损伤率。它说明整体 HOTA 增加与“恢复稳定、原本成功者不受损”不是同一件事，恒速还不能作为已验证安全的新方法。

恢复事件有 51 个删失、17 个长 gap 事件，且以 B0 缺失前可匹配为条件。事件指标不能解释全部 7,565 帧的 HOTA 差异，更不能外推成总体失败率。长 gap 全部为零成功是证据不足，不是安全证明。

## 3. 单步与闭环反转有信息量，但诊断范围比“机制分析”这个名字窄

同 B0 状态诊断中，learned 的目标 IoU 均值约 0.617，高于恒速 0.522；即时首轮正确匹配为 555/562/559，高于恒速 509。但是 **KF 的目标 IoU 为 0.625、即时正确匹配为 575，又高于 learned**。因此准确描述是 learned 优于 CV 的这组单步代理量，而不是 learned 具有最优的单步预测或匹配。

四个注册条件全部针对 learned 相对 CV 的聚合劣势。它们未触发，正确含义是：没有找到这四种、达到预定幅度的平均劣势。按预算规则停止当前分支合理，但这不是穷尽竞争解释后的机制否定。

尤其需要保留三个边界：

1. **状态范围不同。** 诊断共享 B0 的状态与历史；自然运行中每个方法演化出自己的历史、ID 和生命周期。该诊断不识别这些差异的因果作用。
2. **干预与采样范围不同。** 自然闭环会在全部 eligible 首轮轨迹上替换框；既有审计记录三个 learned 运行分别替换约 8.96 万次。机制诊断只检查 831 个恢复事件的重新出现帧（829 个可用），不能据此解释所有非事件帧或全部轨迹的累积变化。
3. **即时匹配不等于输出身份恢复。** B0 的 575 个即时正确匹配中仅 158 个满足 reconnect；另有一个 reconnect 没有即时首轮正确匹配。内部匹配、后续阶段、输出条件及 GT 对输出的匹配位于不同层次。既有记录还不足以把这道差距唯一归因到某个环节，也不应据此指认实现错误。

还应区分 gap 定义：离线 `frame_gap` 为目标帧减最后历史观测帧；共同事件 `missing_length` 是 GT—检测匹配不可用的连续帧数。在线 tracker 的历史又可能关联到其他检测。因此离线 650 个 gap16–31 样本与闭环 17 个同名分桶事件不是同一总体，不能直接对比成功率或解释为大量样本消失。

这些边界不改变闭环 NO_GO，也不构成自动追加一轮 P1 实验的理由。它们只是限制我们能从负结果中得出的结论。

## 4. 现在应怎么推进毕业设计

**保留完整实验基础，关闭当前实现路线。** 现有数据、检测缓存、KF/CV 双对照、统一接口、官方评测、成功损伤指标都可复用。环境和算力不是这轮暴露的主要限制，不必重新下载数据、重训检测器或换更大模型。

下一阶段只做一次有边界的研究路线选择：提出少数候选问题，逐个说明现有证据、竞争解释、最近先例、最小实验、正负结果会改变什么决定，再选择一个实现。不要先决定必须保留 FM，也不要把前期诊断量直接当作方法创新。

从已有材料出发，一个值得列入候选、但尚未验证的问题是：**在固定检测下，能否根据可在线观测的关联证据决定何时干预原有匹配，从而减少“救回少量失败、同时破坏成功”的代价？** 它将目标从平均框误差转向关联决策与损伤控制；但这只是待审问题，并不意味着要立即给 P1 加门控器。需要先核查相关先例与标签是否可学习，再比较最简单的规则或直接关联模型。若仍依赖历史反馈机制，须作为新的协议，与已经关闭的 P1 分开记录。

另一类候选是观测定位/候选竞争建模。G2 只暴露有限特权改进空间，尚未证明这种改进可由真实输入预测，所以不能凭 D3/D5 直接宣布该方向更有把握。是否转向它，应由同样的文献与最小可证伪比较决定。

这一步的交付物应是一份短的候选比较与选择依据，而不是继续堆协议、审计或做大矩阵。当前负结果足以约束投入，但不足以宣称已经确定新论文贡献。若今后重新考虑 FM，需要先回答“为何多个运动假设比 KF/CV 和直接关联更有用”，不能把更换生成器当作解释闭环失败的替代。
