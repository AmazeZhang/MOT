# E5 失误分析与首轮配对补录完整性审计

**日期：** 2026-11-20<br>
**审阅者：** 新鲜 Codex 代理，同系列 provisional；技能指定的 GPT-5.6-Sol 在本会话不可用。<br>
**总体结论：** `WARN`。数值与事件连接通过；警告针对仅拟合集的事后局部分组和因果解释边界。

| 检查 | 结论 | 依据 |
|---|---|---|
| A. GT 来源 | PASS | E5 的原始分支先保存，再读取 DanceTrack `gt.txt`；[首轮补录](../../../scripts/derive_e5_baseline_pair_trace.py)不读 GT，[事后连接](../../../scripts/summarize_e5_pair_trace.py)才读取。 |
| B. 分数归一化 | PASS | E5 评价为 GT 历史锚点五帧正确输出的原始计数与差值，没有用模型输出最大值归一化。 |
| C. 结果与连接 | PASS | 独立重核 24 段原始、评分、配对文件哈希和 576 个唯一 `(视频, 帧, track, 锚帧)` 键；五帧输出重新对 GT 评分与全部原始字段、E5 汇总一致。529 同选、47 分歧、414 两支均损伤其他锚点等计数重现。 |
| D. 执行路径 | PASS | 事件拆解、正常父回放及事后连接均有对应输出和来源哈希；独立 CPU 重放一段至抽样事件，逐帧 E3 C/E 相同，首轮七个检测框/分数与缓存误差最大约 `1.14e-13`，配对一致。 |
| E. 范围 | WARN | 24 段 train-fit、576 个被选中且窗口可能重叠的事件；没有 train-heldout、完整序列方法或官方 TrackEval。事后分组不能升级为新的预写晋级门。 |
| F. 类型 | real_gt/posthoc | 真实数据集 GT 用于事后标签；基线首轮配对回放不读 GT。 |

审阅特别校正两处措辞：414 次共同受损事件中，每支各有 **400** 次移除一个与检测 GT 身份的历史 C 锚点相符的原首轮配对；两支均如此为 **398** 次，至少一支如此为 **402** 次。两支“均有其他锚点受损”不保证受损的是同一 GT；独立复核显示 388 次有重叠受损 GT、26 次没有。移除原配对由强制规则机械产生，但不能单凭并存计数把全部五帧损伤归因于此。

“无目标正检测标签”的 343 次必须使用固定匈牙利/IoU≥0.5 口径：47 次无历史目标 GT 锚点，107 次目标当帧未标注，64 次目标当前有 GT 但无 IoU≥0.5 的高分框，125 次有重叠高分框但全局一对一匹配分给别的 GT。不能称为 343 次检测器漏检。

补录文件检查了检测数量与所选 ID，但未逐一保存全部 576 次请求框坐标的断言；独立抽样重放核对了一个事件的全部框。审阅另发现 `read_detection_cache` 仅给高分行保存 ID，而 E5/补录用 `zip(高分 ID, 全部缓存行)`；若未来出现低分行排在高分行前，映射会失效。本轮直接 CSV 检查 576 个事件的高分 ID 顺序均正确，未见此偏差。该风险不改变本轮结论。审阅 trace 位于 Git 忽略的 `.aris/traces/experiment-audit/2026-11-20_run02/`。
