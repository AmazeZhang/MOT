# S05–S06 复盘：主方案失败，但无额外风险惩罚分支值得保留

日期：2026-11-24；审阅版本 `54d03cc`。本轮是 Git 内证据与代码审阅，没有连接服务器、训练、运行 tracker 或独立重算官方评测。数据来源为 [S05 报告](../reports/diagnostics/s05_visual_decision_coverage_20261123/README.md)、[S06 retry3 报告](../reports/feasibility/s06_component_selector_seed13_retry3_20261124/README.md)。本地复算结果在 [derived_summary.json](audits/s05_s06_local_review_20261124/derived_summary.json)，可用 [只读复核脚本](../scripts/review_s06_git_evidence.py)复现到新文件。

## 1. 判断

**不将本轮归为“完全没有有效内容”，也不将其升级为“创新方法已经成立”。** 原定 Context-risk 主门确实失败，应结束 S06、不续跑 seeds 37/73；计划内的 Context-no-extra-risk 则出现真实完整序列上的描述性正向差异，是值得保留的研究线索。它仍受单 seed、重复使用的开发集、收益集中及不充分机制对照约束。

这里“无额外风险”仍预测 g/h 并按 `g_hat-h_hat` 决策，并非完全不考虑损伤；risk 使用 `g_hat-2*h_hat`。实验比较的是额外惩罚强度及相关决策行为，不能解释为有/无一切风险意识。

先做现有产物的学习质量核查，再判断是否另立新问题。不要为了获得正结果修改 S06 的门槛、权重或 checkpoint，也不要因主门失败丢弃预先列出的次要结果。

## 4. 机制结论为何还不成立

### 4.1 选模策略导致学习阶段不对等

训练实际每 epoch 抽 208 个动作，分成 128+80，合计两个 optimizer step。Local 选 epoch5，即约 10 步；Context 选 epoch30，即约 60 步。六个 Local checkpoint 的内部开发风险策略指标完全相同，协议按最早 epoch 打破平局，最终将很早期的 Local checkpoint 同时用于无额外风险策略。Context 的前五个 checkpoint 也打平，最后一个才改善。

这不是使用 evaluation8 偷选 checkpoint；执行遵循了选模规则。但**该规则对当前几乎不动作的风险策略缺乏区分力**，使次要无额外风险条件的架构比较混入训练进度差异。此前建议采用风险策略选模且所有策略共用 checkpoint，是设计层面的限制，不能只归因于服务器实现。不能据此说“Context 胜 Local 就证明上下文有用”。

训练 MSE：Local epoch5 为 0.178744，epoch30 为 0.078844；Context epoch30 为 0.055675。它们来自逐轮重采样，不是固定样本验证损失。由原有标签计算，按同样视频均衡权重的全训练集常数零预测期望 MSE 为 0.135606，常数均值预测为 0.101068；这些只作为学习质量的参照，**不是同一随机 batch 的严格模型比较，也不是泛化指标**。需在固定 train18/internal-dev6 样本上重新导出已有 checkpoint 的误差才能下结论。

### 4.2 额外损伤惩罚依赖尚未验证的标定

保持 M 原匹配时，按定义 `g=h=0`。但 Git 导出的 Local 无额外风险案例里，M 动作的预测 g 均值约 0.425、h 约 0.423；Context 对应约 0.069/0.116。案例是全部改动加少量不变对照，不能拿这些均值估计总体校准误差，但足以说明绝对预测未准确满足已知零点。

代码还让预测的 M 分数参与候选 argmax，之后才以 `best_score>0` 决定是否保留 M；没有把不干预的收益固定为解析零点。这不是官方指标造假，冻结协议也未细化该实现；它说明实际决策受多个预测偏差影响。`g_hat-2*h_hat` 的负值不能直接解释为可靠识别风险。现有结果只支持“当前模型+当前惩罚策略未成功”，不能推出所有风险建模无效。

未来新方法可检验固定 M=0 的相对效用/排序设计，但不能现在修改旧输出或在 evaluation8 上扫描惩罚系数。

### 4.3 既有审计中的两项偏离确实影响归因

代码核查确认：实际按 action examples 而非冻结的 components batching；末尾 80 个动作仍以 `/128` 缩放梯度。Local 的两个邻边输入全部置零，导致 8,192 个权重结构性无作用；实际参与输入的参数为 17,602 对 25,794，相差约 46.5%。这些不会使已导出官方数值消失，但削弱严格方法对照。

此外，Local 也输入预先计算的同行/同列竞争 margin。因此二者比较的是**额外可学习邻边聚合**，不是“完全没有竞争信息”对“有竞争信息”。V1 的宽泛表述需保留限制，不能从这组结果确认。

仍需补充的小缺口：

- S06 指标表的 `source_artifact_id=s06_official_trackeval` 未在 artifacts 清单定义；部分报告文件也未入清单。应补权威原始评测索引/摘要和源码/运行锁的可解析引用，不能仅写一个集合名称。

这些缺口不自动否定已有评测，但限制研究端进一步诊断。不要为了补格式重训或覆盖旧报告；增加有来源的补充包即可。

## 6. 下一步：一次既有产物体检，然后做方向决定

继续保留 S06 的 STOP。当前不跑 seeds37/73、不改惩罚阈值、不重选 evaluation8 最佳 epoch，也不启动 FM。建议服务器最多用一个工作日、8 CPU 核小时完成以下只读/CPU 推理补充，原模型和训练数据不改：

1. **固定样本的学习质量。** 对已经保存的 Local/Context 六个 checkpoint，在既有 train18 与 internal-dev6 上导出每个分量/动作的 g/k、h/k 标签、预测、动作排序、是否被拒绝、M 零点偏差；标记无法标注项。比较固定样本误差、常数零/训练均值参照及同 epoch 的两个模型。复用原归一化；不做梯度更新，不根据 evaluation8 选择新 checkpoint。样本不足以做精细校准曲线时直接给原值和计数。
2. **补真正可读的案例。** 优先导出 0074、0032 的收益视频及 0049、0023 的退化视频中的已有变化决策，连同完整分量配对/分数/合法边、必要的前后坐标和全部受影响身份。把整段描述与当帧代理分开；仅检查既有轨迹，不强行声称单个动作导致整段收益。
3. **补来源接口。** 完成 artifact ID、精确序列、checkpoint/源代码哈希及运行命令引用。更新 A2A 入口，保留原实验决定和所有负结果。

只有这次体检支持“确实学会了可迁移的动作排序”，才值得另立一个新协议：以无额外风险/相对效用为主问题、M 动作解析零点、真实有效容量对照、component batching、能区分学习进展的统一 checkpoint 规则，并单独安排未用于新调参的最终评估。先验选择应从本轮教训出发，不把已看过的八段重新命名为新留出。若模型排序接近常数、关键收益只能由一两个视频解释，应优先转向成熟学习关联基线的具体失败研究，而不是继续加小规则。

这一步不需要更多 GPU。当前更紧迫的是监督覆盖、选模可辨识性及公平对照。已有工程积累和次要正向结果值得利用，但毕业设计的创新证据还需要新方法相对强基线的可重复优势与清晰机制。
