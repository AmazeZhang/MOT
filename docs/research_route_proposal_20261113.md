# P1 停止后的研究路线建议（2026-11-13）

**建议：把下一轮问题收缩为“学习一次关联改动的后续收益与损伤”，先验证可学习性，再决定是否作为毕业设计主线。** 不继续扩大 P1，不以 FM 为必须保留的模块，也不马上重建端到端 tracker。

这是一份研究建议和小规模试验设计，不是已冻结协议、已实现方法或已证明创新。初步检索已经发现“自适应关联、保护稳定轨迹、学习跟踪决策”有大量先例；下面的具体差异仍需源码和全文级核查。本轮只写方案，不执行新训练、服务器操作或 Git 提交。

## 1. 先明确我们已有和缺少的东西

已有事实来自 [11 月 13 日复盘](experiment_review_20261113.md)：

- P1 三个 seed 的自然闭环都低于 B0 和恒速，当前方案停止合理。
- 恒速总体更好，却损伤 20/81 个 B0 成功对照；它也是下一条路线必须面对的强对照。
- 同 B0 状态下的即时预测/匹配次序与完整闭环次序不同。尚不能确定原因，但已经说明用单步代理指标选方法不充分。
- 检测缓存、真实轨迹历史、分支接口、官方评测和共同恢复事件都已具备。

尚未成立的假设是：**在只使用当前和过去信息的条件下，能否预测某次具体关联改动对后续身份的净影响？** 不应把“确实存在损伤”偷换为“损伤一定能预测”，也不应把两个全程策略的结果之差当成某个局部改动的标签。

毕业设计需要形成可解释的方法和完整证据。现在最重要的是找到一个能以较低成本得到正/负答案的问题；拥有多张 GPU 不构成采用复杂生成模型的理由。

## 2. 三条路线的取舍

| 路线 | 能复用什么 | 核心风险 | 本轮判断 |
| --- | --- | --- | --- |
| 继续改运动模型或换 FM | P1 样本、训练器 | 当前闭环失败未被更强运动模型这一假设解释；复杂度增加，先例也多 | 暂缓，不是永久否定 |
| 检测定位/观测可靠性 | G2、固定检测、KF | 特权框修正空间未证明可预测；定位不确定性与置信度融合已有工作；部分方法需要 NMS 前输出 | 保留备选，不与主试验同时展开 |
| 关联改动的收益/损伤学习 | B0/CV、真实状态、共同事件、官方评测 | 标签与真实收益可能不一致；在线状态漂移；与已有决策学习重合 | **优先做有界可行性试验** |

选择第三条是基于现有工程、问题可检验性和试错成本，不是认定它比其他路线更有创新。若试验失败，也不能用“换一个更大网络”无限延长。

## 3. 文献给出的约束

截至 2026-11-13 的定向检索发现以下直接相关先例。只概括与本方案有关的部分，不比较论文绝对分数。

| 先例 | 已有内容 | 对我们主张的限制 |
| --- | --- | --- |
| [Learning to Track，ICCV 2015](https://cvgl.stanford.edu/papers/xiang_iccv15.pdf) | 将跟踪建模为决策过程，在训练视频跟踪中学习关联策略 | “把关联当决策学习”不能作为首创 |
| [Multi-Agent RL for MOT，AAMAS 2018](https://www.ifaamas.org/Proceedings/aamas2018/pdfs/p1397.pdf) | 使用轨迹管理动作和联合跟踪回报训练共享策略 | “考虑未来/优化跟踪而非局部代理”本身也不新 |
| [DeconfuseTrack，CVPR 2024](https://arxiv.org/html/2403.02767v1) | 将混淆关联分为子问题，并选择性引入外观线索 | 分解冲突与选择性干预均有近邻先例 |
| [UTrack，ECCV 2024 Workshop](https://arxiv.org/html/2408.17098v1) | 从检测分布提取定位不确定性，用于 KF 观测噪声和关联 | 不能把检测分数当定位方差，也不能泛称首次建模观测不确定性 |
| [TrackTrack，CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Shim_Focusing_on_Tracks_for_Online_Multi-Object_Tracking_CVPR_2025_paper.html) | 轨迹视角关联与轨迹感知初始化 | 更改匹配顺序/保护已有轨迹不是充分差异；其检测池也与本项目不同 |
| [Sentinel，Scientific Reports 2026](https://www.nature.com/articles/s41598-026-43938-2) | 根据轨迹状态调整关联，并管理轨迹生存 | “风险感知、保护稳定轨迹、积极恢复不稳定轨迹”的宽泛叙事直接重合 |
| [OATrack，2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13517331/) | UAV 场景的检测—轨迹质量门控、状态保护与渐进匹配 | “质量门控＋状态保护”不能单独宣称新颖 |

因此不推荐把方法简单命名为“置信度自适应 SORT”，再加几个阈值作为贡献。拟检验的较窄差异是：**在明确的可执行关联动作之间，利用同状态、同后续输入的成对分支回放生成增量收益与损伤标签，学习保留基线还是接受改动。** 是否已有完整等价方法尚未确认；不得写“首次”“未有工作”。

## 4. 优先方案：先学习改动是否值得，不生成新运动

### 4.1 首版动作空间尽可能小

保留两个不训练的关联提案：

- A0：当前 B0/KF 产生的首轮匹配。
- A1：在同一真实 tracker 状态下，采用现有恒速外推得到的首轮匹配。

不引入旧 P1 checkpoint、ReID、检测器重训或 FM。这样新结果归因于选择机制，而不是同时换运动模型。

不能每条轨迹独立切换匹配，那会造成同一个检测分给两条轨迹。建议从 A0 与 A1 的匹配边对称差中提取完整连通分量：轨迹和检测是两类节点，一个分量内整体采用 A0 或 A1，分量外保持 A0；重新计算未匹配集合。一对一合法性可独立验证。这是结构设计，不预先声称是新算法。

首版每帧最多接受一个分量的改动，避免同时接受多个局部动作而误把效果视为可加。若两个提案相同，就保持基线。它只保留首轮匹配合法性，不保证后续关联、生命周期或效果独立。

### 4.2 核心工作在标签，而非网络规模

只在 motion-train 建立真实 B0 状态，按预定、与 GT 结果无关的规则采样分歧分量。对同一时刻的完整 tracker 状态做两个独立副本：

1. 副本 0 执行 A0；副本 1 仅在选定分量执行 A1。
2. 两个副本随后都使用同一基线策略、同一检测缓存运行 H 帧，首选草案 H=10。
3. GT 仅在训练标签构建阶段判断真实输出的身份保持、丢失和错误关联；未来检测/GT 不进入选择器特征。
4. 保留“恢复了谁”“伤害了谁”，而不仅是一个总分。一项动作可能同时产生收益和损伤。

首版标签可用 t−1 时刻可判定的 GT—已有轨迹锚点，在未来 GT 存在帧上统计原 ID 正确输出的帧数差，并记录相对 A0 新增丢失/错配的锚点。评价所有可判定锚点，包含分量外轨迹，不能只算被救目标。GT 缺失不猜测身份；边界删失和未锚定目标单列。这个代理不覆盖新生目标的全部代价，也不是 HOTA，因此最终一定回到完整闭环官方指标。

“如果采用另一个动作会怎样”在这里是确定性软件系统内的成对干预，不是对真实世界遮挡因果的识别。分支间必须隔离 ID 计数器、KF/ORU 缓存、历史、随机状态；A0 续跑要与原始回放一致。不能靠修改输出 ID 来制造恢复。

两条完整视频结果之间做事后差分不能替代上述标签：它们在当前帧以前已经有不同的状态和 ID。H=10 也不是长程真实价值；H=5/20 只能作为提前登记的敏感性分析，不能事后选最好窗口。

### 4.3 选择器从线性模型开始

候选特征全部来自时刻 t 或更早：两提案的分歧规模、匹配分数及竞争间隔、轨迹年龄/缺失间隔、观测残差、检测分数、尺度变化、周边候选数量。规范化只在训练子集拟合；不输入 GT、未来帧、未来输出、序列身份或事后成功标签。

先用线性收益回归与损伤概率分类器；只有有用信号存在，才比较一个两层小 MLP。按预测收益与损伤代价形成分数，只有超过训练内校准阈值才接受 A1，否则 A0。损伤概率须检查校准，不能因为使用 sigmoid 就称为可靠概率，更不能声称形式化安全保证。

训练状态来自 B0，但部署会改变后续状态，分布偏移仍然存在。首轮自然闭环就是对这个问题的实际检查；不预先把 DAgger、在线 RL 或重采样循环也加入，避免扩成无法收束的工程。

## 5. 三个必须区分的假设

| 候选解释 | 预期观察 | 区分实验/失败含义 |
| --- | --- | --- |
| H1：当前信息能辨认有益与有害动作 | 在按视频隔离的训练内留出集，相同干预数量下比随机/简单间隔规则保留更多净收益 | 固定动作集与覆盖率比较；无改善则不启动复杂选择器 |
| H2：后续身份标签比即时匹配标签更有用 | 同特征、同模型、同预算，用短程标签训练的选择器在闭环损伤/收益上更好 | 即时标签 vs H=10 标签是核心消融；相当则不能主张未来监督的必要性 |
| H3：收益能在策略自己的状态上保持 | 自然闭环优于简单选择或形成更好的收益—损伤折中 | 离线可选择、闭环无收益说明当前方案仍失败；不能继续宣传离线优势 |

竞争解释还包括：仅减少干预次数就降低损伤、只对特定视频有效、GT 锚点选择偏差、标签与 TrackEval 输出不同、历史状态分布改变。对照必须对应这些解释，而不是只与原始 KF 比。

## 6. 用约一到两周作决策周期，不作效果或工时承诺

### 阶段 A：两天左右，先确定动作与标签能否成立

- 补读最近的全文/代码，重点确认与决策学习、分解关联、Sentinel 的差异。若差异仅是换特征或改阈值，先重构问题。
- 从原 32 段 motion-train 再按视频固定 fit/calibration 划分，建议 24/8；原 8 段 motion-dev 不参与训练、归一化或校准。保存清单，不按新结果挑视频。
- 在 fit 子集按固定哈希选 4 段，最多 200 个分歧分量，做双分支工程验收、标签审阅、耗时与内存测量。样本数是工程上限，不是功效计算。
- 运行前固定标签语义、数值门与资源预算；本建议中的数值不能事后修改成“原本就预注册”。

**停止条件：** 状态副本难以可靠隔离、标签不能反映身份输出、可用动作基本没有正收益，或最近先例已完整覆盖拟做方法。200 个样本结果只能用于探索；少量正例既不保证可学习，少量零收益也不普遍否定方向。

### 阶段 B：随后三到四天，判断是否可学习

- 最多扩至 20,000 个分歧分量、每段视频设上限，按预定哈希采样，保留收益/损伤/无变化及不可评价样本的计数。训练内留出按完整视频隔离，禁止打散相邻窗口。
- 在同一动作和覆盖率下比较：不干预、随机干预、固定竞争间隔规则、即时标签线性选择、短程标签线性选择。随机重复只是工程基线，不当作独立视频样本。
- 特权选择仅展示该动作集、该状态与有限窗口里的可选空间；绝不能把它当可部署结果或全程最优上界。
- 若线性短程标签已有稳定信号，可加一个小 MLP；不做大架构搜索。若只是随机挑少一点也一样好，学习模块没有获得支持。

此阶段的具体最小效应、覆盖率点和损伤权重必须在对应留出结果前固定。建议只校准一个操作点，不跨很多阈值挑最漂亮曲线。证据不足的结果记为不确定，在本轮预算内不升级。

### 阶段 C：有信号才做一次完整 motion-dev 闭环

比较 KF、全程 CV、简单间隔规则、即时标签选择器、短程标签选择器；随机对照保留必要的匹配覆盖率结果。模型结构、阈值和训练预算先锁定，若采用随机训练的 MLP则报告全部三个 seed。

本路线的首要目标拟定为：**在接近最强简单 CV 的总体指标下，明显减少其成功对照损伤，同时不牺牲净恢复。** 可供冻结时讨论的开发门草案是：HOTA/AssA 相对 CV 下降各不超过 0.1 点；平均损伤不超过 10/81（CV 为 20/81）；恢复减损伤不低于 CV 的 +3；同时逐 seed 检查对 KF 的退化。它们是工程决策阈值，不是统计非劣性界或安全保证，且不得与另一个宽松门事后择优。

这组门还不证明学习必要性：必须同时胜过预定简单规则，并用同模型即时标签对照检验 H2。完整官方 HOTA/AssA/IDF1/DetA、逐视频结果、原 831 事件、额外干预分布及延迟都报告。原 motion-dev 已被多次查看，仍是开发证据，不称为独立确认。

如果主试验失败，本轮结束，不通过换 backbone、扩大窗口或追加概率头续命；只有发现明确工程错误时做保持协议的技术重跑。若成功，再规划第二 tracker、第二数据集和锁定后官方 val 的确认，而不是立刻增加三四个模块。

## 7. 算力、环境与工作量

- 前半段主要是 CPU 回放、分支复制和特征表，先测 200 样本实际成本。首轮建议资源上限为 32 CPU 核时、4 GPU 卡时；这是人为预算，不是运行时间估计。若按实测外推超限，缩小样本并标明结论范围，不自动扩大预算。
- 线性模型用 CPU；小 MLP 预计无需多卡训练，具体 batch/显存以实测为准。使用服务器时物理 GPU0 永久禁用；仅在检查占用后选择 GPU1–7，记录 `CUDA_VISIBLE_DEVICES` 和物理/逻辑映射。3060 是否可用须单独遵守其机器规则，本轮不默认调用。
- 沿用现有环境，不重装 CUDA，不新增大数据。仓库仍为 `/home/imc/yzy/MOT`；标签、回放和结果放 `/media/imc/data/mot-data`，机器记录放忽略的 `local/`。
- 若要形成毕业设计，工作量应来自可复查的动作/标签构建、轻量选择方法、严格的必要性消融和跨条件验证；不靠网络参数量充数。能否满足学校要求还取决于最终证据和导师标准，当前不保证该候选已足够创新。

## 8. 如何决定 FM 的去留

当前将 FM 从主线必选项移到候选工具。只有后续证据表明“现有动作集中缺少正确身份的可行候选”，而多个运动假设能补足这种缺口，并且简单 Gaussian/MDN 不能解决时，才值得重新讨论 FM。即使新的选择器有效，也不会自动证明需要生成器。

近期精确下一步：**先完成阶段 A 的协议与最小双分支数据构建，实现仅限于验证标签和可学习性；看完这个有界试验再决定正式方法。** 本轮未启动阶段 A，实现和运行仍是后续工作。
