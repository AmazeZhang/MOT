# 研究监管与创新有效性台账

这里是项目中“创新性”与“有效性”的统一入口。它用于并行协作：科研 agent 可继续查文献和审核主张，实验线可按统一协议产生证据，但两边都不能在没有来源或运行记录时把计划升级为结论。

## 当前研究问题

> 在固定检测候选池与严格在线多目标跟踪中，当目标出现短时观测缺失与近邻身份竞争时，关联导向的运动分布学习是否比单点预测、Gaussian 或 MDN 更能改善闭环身份稳定性？

当前贡献类型：经验方法＋因果式消融＋系统评价。暂未锁定投稿地点。

## 并行工作边界

### 科研 agent

1. 以 `innovation_registry.md` 中的 claim ID 为单位检索，不做没有主张边界的泛文献综述。
2. 每个最近先例至少记录问题、机制、关键洞察、领域、证据定位和与本项目的差异。
3. 新文献只能使主张状态保持、降级或收缩，不能直接宣布实验有效。
4. 发现高重合时，在台账中记录阻断文献和建议的重构方向。

### 实验/工程线

1. 每个 run 必须对应 `experiment_matrix.csv` 中的 run ID，并保存数据、代码提交、配置、种子、环境、输出和评测命令。
2. 只有真实完成的 run 才能从 `NOT_SUPPORTED_BY_PROVENANCE` 升级。
3. 优先运行能否定主张的对照，不用追加模块规避负结果。
4. 预测指标与闭环关联指标分开；oracle 改善不自动升级为跟踪改善。

## 合并规则

1. 所有新主张先加入台账，再加实验或参考文献。
2. 文献侧与实验侧不直接互相覆盖结论；由人工在检查点合并。
3. 任何“首次”“显著优于”“证明”主张都默认失败关闭：没有先例检索或运行 provenance 时不得使用。
4. 当最近先例、实验协议或结果改变时，同步更新本文、`innovation_registry.md` 和相应决策记录。
